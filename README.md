# MasterMind NSU

Решение кейса **Budget-Aware Token Estimation for Agentic AI** на openJiuwen. Судейский запуск использует обновлённую проверку выполнимости `triggered` (`triggered_verification_v3`). Агент обрабатывает задачи последовательно и сохраняет результаты по мере готовности.

## Сборка

Команды из корня репозитория.

```bash
docker build -t mastermind-nsu:judge .
docker images mastermind-nsu:judge --format '{{.Repository}}:{{.Tag}} -> {{.Size}}'
```

Образ использует `python:3.11.15-slim-bookworm` и `openjiuwen==0.1.20.post1`. Зависимости из `requirements.lock` устанавливаются при сборке. Файлы токенизации Qwen входят в образ и загружаются с диска. Для выполнения команд агента нужен Linux с поддержкой Landlock ABI 3 или новее и seccomp.

## Запуск

Задайте `TASKS` абсолютным путём к каталогу задач. В каждом подкаталоге должен быть `task.json` с полями `instruction`, `task_type` и `reward`. Поле `task_id` можно опустить, тогда используется имя подкаталога. Агент берёт входные файлы из `workspace/` внутри задачи, а при его отсутствии читает их из каталога задачи.

Перед запуском экспортируйте `LLM_BASE_URL` с адресом совместимого с OpenAI прокси (обычно с `/v1`) и `LLM_API_KEY` с его ключом. Экспортируйте `BUDGET`, если для прогона выделен бюджет в взвешенных токенах. Для каждого прогона используйте свежую копию входных задач с правом записи для пользователя контейнера. Ранее созданные `answer.txt`, `result.json` и `trajectory.jsonl` в каталогах задач препятствуют повторному запуску на той же копии.

```bash
export TASKS=/absolute/path/to/tasks

timeout -k 1000s 1h docker run --rm \
  -e LLM_BASE_URL -e LLM_API_KEY -e BUDGET -e HOME=/tmp \
  -v "$TASKS:/data/tasks:rw" \
  --read-only --tmpfs /tmp:rw,size=2g \
  --cap-drop ALL --security-opt no-new-privileges \
  --cpus 4 --memory 16g --pids-limit 512 \
  --workdir /app --entrypoint python \
  mastermind-nsu:judge /app/run_agent.py --tasks-dir /data/tasks
```

В среде жюри используйте `--network hack-net` для доступа к прокси. Для локального запуска можно добавить `--user "$(id -u):$(id -g)"`, чтобы выходные файлы принадлежали вашему пользователю.

Образ автоматически загружает `competition/profile.json`. По команде `python /app/run_agent.py --tasks-dir /data/tasks` запускается `triggered` на `qwen3.8-27b` с локальным счётчиком токенов и паузой 1,5 секунды перед каждым запросом. Задачи идут в порядке имён каталогов. Внутренний предел прогона составляет 3500 секунд, предел попытки — 180 секунд и 12 шагов.

## Результаты

- `math`, `search`, `data_analysis` — текстовый ответ в `answer.txt` рядом с `task.json`.
- `coding` — исправленные исходники по исходным путям. Если в задаче есть открытые Python-тесты `test*.py`, агент проверяет их перед публикацией и сохраняет предоставленные файлы тестов.

Записи заменяются атомарно и синхронизируются с диском до перехода к следующей задаче. Ответы и исходники доступны для чтения проверяющему с другим UID при доступе к каталогу задач. Статус попытки, вердикт и стоимость проверочных вызовов сохраняются в `result.json` рядом с `task.json`. Ход попытки записывается в `trajectory.jsonl`. Итоговая сводка выводится в stdout в формате JSON с полем `"policy": "triggered_verification_v3"`.

## Проверка выполнимости

Для поддерживаемых форматов контроллер вычисляет ответ или выявляет противоречие без вызова модели. Это целочисленные выражения и равенства, точный поиск в CSV/JSON и отдельные расчёты выручки по курсам.

Для остальных задач агент обращается к прокси. Когда решатель предлагает ответ, отдельный запрос к той же модели проверяет выполнимость по исходной инструкции и файлам. Для блокировки публикации контроллер сверяет цитаты из вердикта с оригиналами. Отказ модели также можно перепроверить и вернуть задачу решателю. При нехватке шагов, времени или полного контекста предложенный ответ может быть опубликован без проверки выполнимости.

В живом эксперименте на 50 синтетических задачах эта версия решила 36 из 36 выполнимых и оставила 14 из 14 невыполнимых без публикации. В отдельном наборе она решила 15 из 16 выполнимых и оставила 8 из 8 невыполнимых без публикации. Траектории содержали шаги решателя, вердикты и расход вызовов. Оба прогона измеряли качество на синтетических данных без общего численного ограничения токенов.

## Учёт токенов

Расход оценивается как `output_tokens + input_tokens / 10`. Вход считается по шаблону чата Qwen. Доступный текст рассуждений входит в выходные токены. При скрытых рассуждениях или неполном завершении счётчик берёт большее из двух значений — токены полученного текста или запрошенный предел выхода. Локальные оценки помечены `local_qwen_estimate`. `BUDGET` задаёт порог для отчёта об остатке и превышении. Остановку по фактическому расходу выполняет среда жюри.
