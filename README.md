# MasterMind NSU

Решение кейса **Budget-Aware Token Estimation for Agentic AI** на openJiuwen. Агент оценивает задачи до первого запроса к модели, решает их по одной и сохраняет результат каждой завершённой задачи сразу.

## Сборка

В корне репозитория выполните:

```bash
docker build -t mastermind-nsu:judge .
docker images mastermind-nsu:judge --format '{{.Repository}}:{{.Tag}} -> {{.Size}}'
```

Образ использует `python:3.11.15-slim-bookworm` и `openjiuwen==0.1.20.post1`. Версии Python-пакетов зафиксированы в [`requirements.lock`](requirements.lock). Зависимости устанавливаются при сборке. Веса оценщика и файлы токенизации Qwen входят в образ и загружаются с диска. Для выполнения команд агента нужен Linux с поддержкой Landlock ABI 3 или новее и seccomp.

## Запуск

Задайте `TASKS` абсолютным путём к каталогу задач. В каждом подкаталоге должен быть `task.json` с полями `instruction`, `task_type` и `reward`. Поле `task_id` можно опустить, тогда используется имя подкаталога. Агент берёт входные файлы из `workspace/` внутри задачи, а при его отсутствии читает их из каталога задачи.

Перед запуском экспортируйте `LLM_BASE_URL` с адресом совместимого с OpenAI прокси (обычно с `/v1`) и `LLM_API_KEY` с его ключом. Экспортируйте `BUDGET`, если для прогона выделен бюджет в взвешенных токенах. Используйте копию входного каталога с правом записи для пользователя контейнера.

```bash
export TASKS=/absolute/path/to/tasks

timeout -k 1000s 1h docker run --rm \
  -e LLM_BASE_URL -e LLM_API_KEY -e BUDGET -e HOME=/tmp \
  -v "$TASKS:/data/tasks:rw" \
  --read-only --tmpfs /tmp:rw,size=2g \
  --cap-drop ALL --security-opt no-new-privileges \
  --cpus 4 --memory 16g --pids-limit 512 \
  --workdir /app --entrypoint python \
  mastermind-nsu:judge /app/run_agent.py --tasks-dir /data/tasks
```

В среде жюри используйте `--network hack-net` для доступа к прокси. Для локального запуска можно добавить `--user "$(id -u):$(id -g)"`, чтобы выходные файлы принадлежали вашему пользователю.

Образ автоматически загружает [`competition/profile.json`](competition/profile.json). Он выбирает `qwen3.8-27b`, оценщик порядка, локальный счётчик токенов и паузу 1,5 секунды перед каждым запросом. Внутренний предел прогона составляет 3500 секунд, предел попытки — 180 секунд и 12 шагов.

## Результаты

- `math`, `search`, `data_analysis` — текстовый ответ в `answer.txt` рядом с `task.json`.
- `coding` — исправленные исходники по исходным путям. Если в задаче есть открытые Python-тесты `test*.py`, агент проверяет их перед публикацией и сохраняет предоставленные файлы тестов.

Записи заменяются атомарно и синхронизируются с диском до перехода к следующей задаче. Прогноз, статус попытки и журнал вызовов сохраняются рядом с `task.json` в `prediction.json`, `result.json` и `trajectory.jsonl`. Итоговая сводка выводится в stdout в формате JSON.

## Порядок задач и учёт токенов

До обращений к прокси оценщик прогнозирует стоимость и вероятность успешного решения по типу задачи, числу файлов и их суммарному размеру. Для стоимости используется гребневая регрессия по логарифму расхода с поправкой на 80-й процентиль остатков. Вероятность `p_pass` оценивает логистическая регрессия. Задачи запускаются по убыванию `reward × p_pass / max(1, cost_q80)`. При несовместимости весов с параметрами запуска агент переходит к порядку имён каталогов.

Для обучения собрали 600 траекторий на синтетических задачах четырёх типов. Веса обучены на 597 попытках с известным `usage`. Три попытки с ошибками API исключили. Скрытый судейский набор не участвовал в обучении.

Во время решения модель может вернуть `unsolvable`, если обнаружит противоречие или недостающие данные. Тогда агент переходит к следующей задаче без публикации. Предварительная вероятность успеха влияет на порядок, а решение об отказе принимается во время попытки.

Расход оценивается как `output_tokens + input_tokens / 10`. Вход считается по шаблону чата Qwen. Доступный текст рассуждений входит в выходные токены. При скрытых рассуждениях или неполном завершении счётчик берёт большее из двух значений — токены полученного текста или запрошенный предел выхода. Локальные оценки помечены `local_qwen_estimate`. `BUDGET` задаёт порог для отчёта об остатке и превышении. Остановку по фактическому расходу выполняет среда жюри.
